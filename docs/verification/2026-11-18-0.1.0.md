## 运行备注

- pack 进程模型：真实 pack 由 `scripts/process-tree.mjs` 的异步 `runWithTimeout`
  执行，`shell:false`，通过 `process.execPath + npm-cli.js` 调用 Node 自带 npm；
  超时 60s 时终止完整进程树。修复前的同步 `spawnSync(..., { shell:true })`
  DEP0190 与同步阻塞已消除，正向门禁 stderr 不再出现 DEP0190。
- 静态检查失败时，门禁跳过真实 pack 与依赖 pack 清单的秘密扫描，并输出
  `pack 调用：0 次`；只有“非法打包”变异使用 `--force-pack` 保留真实 pack。
- 调用次数：单次正向 `verify-package` = 1 次 pack；单次
  `release-gates.spec.ts` = 5 次（正向 1、非法打包 force 1、README/package.json/
  icon.svg 秘密各 1；导入/React/Fetch/README 披露/locale 披露变异为 0）。
  完整 `pnpm verify` 通过临时计数器实测为 **11 次真实 pack**（`pnpm test` 5 +
  `pnpm test:integration` 5 + 直接 verify-package 1）；计数器仅为本次测量注入，
  测量后已移除，不进入交付。
- 负载/超时：进程树自证（下方）证明 deadline 可终止父子进程；没有延长任何
  既有 5s 测试超时，也没有删除断言。此前一次完整 verify 中两个既有重集成测试
  的 5s 超时抖动作为观察记录保留；2026-11-21 默认高并发运行再次暴露同类 5s
  超时与 capability-probe 时序失败，按下方根因对照收敛并发后复测，未通过改测试
  或放宽超时掩盖。
- 测试执行并发：`vitest.config.ts` 默认固定 `maxWorkers: 1`（文件串行），不再依赖
  命令行临时参数。Vitest 5 非 watch 模式的默认并发为 `availableParallelism() - 1`
  （本机 16 逻辑核即 15 个 worker）；全量会同时运行 Native/PTC 真实 DSH fixture
  （Electron Node 加载 app.asar 的子进程）、`vitest list`、真实 `npm pack` 与
  CSS 门禁等子进程，以及 capability-probe 的 50ms/100ms deadline race。满并发时
  CPU/IO 争抢会让这些真实子进程逼近既有 5s 测试超时，也会让毫秒级 race 在事件
  循环延迟下失序；单文件运行这些用例每个仅 252–391ms（3 个真实子进程 spec 共
  34 tests / 5.04s），余量远大于 5s，证明超时来自执行资源争抢而非用例本身慢。
  实测 `maxWorkers: 4` 在机器级外部负载下仍出现 11 个真实子进程 5s 超时，不能
  当作稳定保证，因此进一步收敛为本仓库的单 worker 串行执行；未延长任何 timeout、
  未删断言、未改产品行为。
- 根因对照实测（2026-11-21，显式 rc.5）：
  - 高并发失败类：默认 15 workers 下出现真实子进程
    `TestTimeoutError: Test timed out in 5000ms`（父会话记录一次全量 20 个）与
    capability-probe 时序失败；同时并发 2 个 `pnpm vitest run --maxWorkers=15`
    全量可复现（run 1 = 3 failed，`search-output-contract`/`tool-admission`/
    `tool-override` 各 1 个 native 用例；run 2 = 4 failed，同组 3 个 +
    `capability-probes` 的 deadline/settle 用例）。本机空闲时单进程 15-worker
    全量 3/3 曾通过，说明失败与负载阈值相关而非确定性。
  - 4 workers 不是稳定保证：早期 4 个默认配置全量并发（16 workers）与单次默认
    配置全量曾通过（60 files / 1117 tests），但 2026-11-21 后续对照中，默认
    `maxWorkers: 4` 在机器级外部负载下再次出现 11 个真实子进程 5s 超时。
  - 单 worker 对照：`pnpm vitest run --maxWorkers=1` 实测 62 files / 1125 tests
    全部通过；默认配置 `pnpm test`（`maxWorkers: 1`）同样 62 files / 1125 tests
    通过、47.77s，`pnpm test:integration` 12 files / 79 tests 通过、22.20s。
- 机器级并发边界（实测，不阻塞本任务结论）：`maxWorkers` 只约束本仓库自身的
  worker 数，不提供跨进程/跨项目隔离。2026-11-21 03:12–03:13 的一次 `pnpm verify`
  与本机另一项目（`deepseek-harness` worktree `multi-root-forge` 的
  `vitest run packages/experimental/client-ui-forge/tests`）并发时，`maxWorkers: 4`
  仍出现 2 个真实子进程用例 `Test timed out in 5000ms`（CPU 采样 73%/59%/73%）；
  该外部负载退出后（CPU 约 16%/3.8%），同一配置重跑 `pnpm verify` exit 0。单 worker
  消除了本仓库自身并发，但若其他重型套件同时占满机器，仍属外部资源边界；按约束
  未延长 timeout、未删断言，也未把外部负载下的失败写成 PASS。

## CSS 隔离与反向对照

- 正常门禁 `node scripts/verify-css-isolation.mjs`：扫描本包全部最终样式表（`lib/client.js` 中 1 张样式表、51 个类名，含 portal 菜单复用的同一 CSS Modules 表），并与同级**现有只读构建产物** `dsh-project-groups/lib/client.js`（5 张样式表、164 个类名）和 `dsh-auto-expand/lib/client.js`（7 张样式表、57 个类名）做类名交集，结果为 **0**。
- 样式表清点：提取到的样式表数量必须等于产物内 `styleId` 声明数，否则门禁失败；本包 1=1、dsh-project-groups 5=5、dsh-auto-expand 7=7。
- 反向对照 `node scripts/verify-css-isolation.mjs --reverse-control`：只在系统临时目录副本中分别还原本插件与同级插件映射里的旧类名，避免修改任何原产物。实际输出：
  - `reverse-control dsh-project-groups selfOldOnly=0 siblingOldOnly=0 bothRestored=8`
  - `reverse-control dsh-auto-expand selfOldOnly=0 siblingOldOnly=0 bothRestored=11`
  - 结论：单边还原旧哈希不产生交集，说明两侧哈希各自有效；**双方旧哈希同时还原后交集非空（8/11）**，证明该交集检查确实能识别类名冲突，而不是空跑。
- 门禁脚本不会写入、重建或启用/停用其他插件；同级产物只读。
